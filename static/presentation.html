Fraud lives in change.

Paying a known supplier the known way is safe. The loss happens on the day something changes, and no single party can verify the change alone. So Trust Layer diffs every incoming invoice against the supplier baseline, deterministically, with zero LLM calls. Every difference becomes a change-of-state claim:

bank_account_changed

the headline attack, and the honest bank switch

new_supplier

no history at all: ghost companies live here

terms_changed

payment terms drifting beyond 2× the norm

duplicate_financing

the same receivable submitted twice

No claims → auto-approved in under a second. A claim → the claim goes on trial.

The claim goes on trial.

Detector Deterministic diff, no LLM. The only agent allowed to say "nothing happened".
Investigator Works six evidence sources. Gathers facts. Never concludes.
Skeptic Briefed to argue fraud. Same evidence, hostile reading.
Advocate Briefed to defend the supplier relationship. Attacks weak fraud claims.
Arbiter Weighs the debate into a schema-enforced verdict and a safe next step.
↳ no claims? the invoice never enters the loop: auto-approved in <1s
every step emits a heartbeat → the live monitor the audience watches → recorded, replayable runs

Six ways to check one claim.

zwapgrid LIVE API

Invoice interchange + payment history over the real Accounting API. Runtime toggle: mock ↔ live, mid-demo.

bankgirot REAL · PARSED

Mod-10 check-digit validation offline (a failing number was never issued). Owner lookup parses public data, because Bankgirot has no API.

account_registry THE PITCH

"Who owns this account?" The answers it returns here are simulated. Today Sweden can answer only for bankgiro numbers (Bankgirocentralen) or with the account holder's own consent (open banking), and the fraudster controls that consent. More in a moment.

open_payments LIVE API

Real PSD2 payment execution: an approved case pays out through the Payment Initiation API (swedish-giro + decoupled SCA, sandbox).

bolagsverket STUB READY

Company status, address, registration by orgnr. Free public API; onboarding registration pending.

web_intel + invoice_archive MOCK / REAL

Public announcements (mocked) and our own ledger (real SQLite): the field-by-field memory of the relationship.

Every source sits behind one EvidenceTool interface. Mock and real implementations swap per tool, at runtime: the demo runs offline, the architecture runs in production.

Built on the Build Day rails.

Zwapgrid LIVE

Consent-scoped Accounting API: one sync pulls the connected company's real supplier invoices into the same intake as everything else. Live payment history answers the Investigator's questions mid-case.

What we found on the wire: the e-invoice feed carries no authoritative bank-account field. Payment routing hides in free-text notes. An account number off the wire is an unverified claim, so it goes through this pipeline, never around it.

And it writes both ways: demo invoices are pushed back into the sandbox over the same API, so the sync pulls real data end to end.

Open Payments LIVE

Real PSD2 Payment Initiation: OAuth2 client credentials, a swedish-giro payment (bankgiro-routed: every supplier account here already is one), decoupled SCA that finalises in sandbox, and status polled to settlement.

Why it matters: the loop closes. A verdict is not a report: an approved case actually pays, and a blocked one actually does not.

Stated gap: no write-back to the supplier's own accounting system ("paid" lives in our ledger; Zwapgrid's API is read/create-only, verified rather than guessed).

Norway already built the missing piece.

Norway · KAR EXISTS

Konto- og adresseringsregister, run by the banks through Bits: before paying, a bank verifies that the account actually belongs to the person or company being paid. Account-ownership verification as infrastructure.

Sweden THE GAP

The institution already exists: Bankgirocentralen maps bankgiro numbers to owners today, and its public number search proves it. But coverage stops at bankgiro aliases: no accounts, no IBANs, no API. IMY's sandbox with the four major banks concluded account-level sharing needs legislative change (IMY-2024-14275). Open banking can return holder names today, but only with the account holder's consent, and in a fraud the account holder is the mule. The attack in scenario 2 uses an IBAN: exactly the uncovered space.

Our account_registry is not science fiction: it is KAR for Sweden, and Bankgirocentralen is the obvious operator. Extend what it already does for bankgiro numbers to accounts and IBANs, behind an API banks query before paying. The slice buildable today, we built: mod-10 validation plus parsed public Bankgirot ownership.
